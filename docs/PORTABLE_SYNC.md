# 手动迁移与进度同步

Tips 的“迁移进度”用于在 Windows、macOS 和 Linux 设备之间手动搬运普通便签、TODO 与分组。它不是实时云同步，也不是数据库完整备份。

## 使用方法

1. 在源设备主窗口左侧找到“迁移进度”，点击“导出”。
2. 选择保存位置，将生成的 `.json` 文件通过你信任的方式传到另一台设备。
3. 在目标设备点击“导入”，选择该文件。
4. 查看完成提示中的新增、更新、跳过与冲突数量；原设备的数据不会因导出而改变。

进度文件是明文 JSON，普通便签正文与 TODO 文本可以直接被文件读取者看到。请勿把它放在公开网盘或不可信聊天中；迁移完成后按自己的安全需求删除中转副本。

## 数据范围

| 会迁移 | 不会迁移 |
| --- | --- |
| 普通便签与 TODO 的标题、正文、清单项 | `secret` 密文和任何标记为敏感的条目 |
| 完成、归档状态和时间信息 | MCP 客户端、Bearer token、授权与服务设置 |
| 分组（包括空分组）、标签和条目级 MCP 访问选择 | 窗口坐标、尺寸、可见性、置顶和透明度 |
| 稳定 ID 与 revision | 主题、界面语言和其他设备偏好 |

目标设备会用自己的系统凭据库主密钥重新加密导入的正文和清单项。导入的新条目默认不弹出悬浮窗；更新已有条目时保留目标设备自己的窗口状态。

## 合并规则

导入以稳定条目 ID 和 revision 合并，不按标题猜测同一条内容：

- 目标设备没有该 ID：新增。
- 两边内容与状态相同：保持不变。
- 文件 revision 更高：更新普通便签或 TODO，但保留本机窗口设置。
- 本机 revision 更高：跳过，保留本机进度。
- revision 相同但内容不同：记为冲突并跳过，不静默覆盖。
- 本机同 ID 是密文或敏感条目：记为冲突并跳过。

当前格式不会传播删除操作。若一台设备删除了条目，另一台设备已有的同 ID 条目不会因为导入而自动删除。需要跨设备保留进度时，优先使用归档状态。

## 文件校验

当前格式标识为 `tips-progress`、版本为 `1`。导入文件最大 64 MiB，最多包含 2,000 个分组和 10,000 条便签或 TODO；每个 TODO 最多 200 个清单项。Tips 会校验结构、未知字段、UUID、revision、时间戳、分组、文本长度、清单状态和重复 ID，任何失败都会回滚整次导入。

不要手工向进度文件加入密码、token 或 `secret` 条目；此类内容会被拒绝导入。
