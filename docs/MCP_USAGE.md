# MCP 使用说明

Tips 内置一个仅供本机使用的 MCP Streamable HTTP 服务。应用启动后，默认端点是：

```text
http://127.0.0.1:4784/mcp
```

当前版本不会监听局域网地址，也不会因为启用 MCP 而隐式绑定 `0.0.0.0`。

## 创建客户端凭据

1. 启动 Tips，在左侧栏底部点击 **MCP 仅本机 / 管理**。
2. 为 Agent 或终端填写一个可辨识的客户端名称。
3. 填写授权 `group`，并选择 `viewer`、`contributor` 或 `coordinator`。
4. 点击 **创建并授权**，立即把显示的一次性 Bearer token 保存到客户端的凭据存储中。

每个 Agent 或终端应使用独立客户端。这样可以单独撤销某个客户端，而不用同时更换其他连接的凭据。关闭令牌提示后，原始 token 无法再次查看；遗失时请撤销旧客户端并创建新客户端。

创建新的持久化分组后，可以回到同一管理面板的 **分组授权** 区域，选择已有客户端、分组和角色，然后点击 **添加授权**。若该客户端已经拥有所选分组，按钮会变为 **更新授权**，可直接调整角色而不更换 token。客户端卡片中每条授权旁的 **编辑** 会将这组选择带回授权表单；也可以单独撤销该授权。

客户端卡片另有默认关闭的 **允许管理分组** 开关。这是客户端级显式能力：只有用户在主窗口打开它后，该客户端才能调用 `tips_group_create`；新组创建成功后，客户端会自动成为该新组的协调者。`tips_group_rename` 除此能力外，还要求客户端已经是源组的 `coordinator`。仅仅在某个组拥有 `coordinator` 角色，不会自动取得创建其他分组的权限。

## 连接客户端

在支持 Streamable HTTP 的 MCP 客户端中配置端点，并通过 HTTP `Authorization` 请求头发送 token：

```json
{
  "url": "http://127.0.0.1:4784/mcp",
  "headers": {
    "Authorization": "Bearer <一次性令牌>"
  }
}
```

上面的 JSON 只表示通用配置形状；不同 MCP 客户端的字段名和秘密变量语法可能不同。优先使用客户端提供的系统凭据库、秘密变量或环境变量功能，不要把真实 token 写进仓库、URL、截图或日志。

服务使用无会话的 Streamable HTTP，请求协议版本为 `2026-07-28`。支持该协议版本的 SDK 会自动发送 `MCP-Protocol-Version`、`Mcp-Method` 以及工具调用所需的 `Mcp-Name` 请求头。

## 分组和角色

`group` 是稳定的共享任务空间，不是标签。它会被去除首尾空白并转为小写，最长 96 个字符；可以使用 Unicode 字母和数字，以及 `-`、`_`、`.`、`/`。空路径段、`.` 和 `..` 不可用。

| 角色 | 读取 | 条目创建、编辑、完成 |
| --- | --- | --- |
| `viewer` | 是 | 否 |
| `contributor` | 是 | 是 |
| `coordinator` | 是 | 是；也可在具备独立分组管理能力时重命名自己协调的分组 |

“允许管理分组”是客户端级能力，不由上述单个分组角色自动推导。它允许创建新分组；重命名则额外检查源组的 `coordinator` 角色。

一个客户端可拥有多个分组授权。管理面板支持为已有客户端追加分组、调整角色、撤销单个分组，或撤销整个客户端。客户端撤销立即使其 token 失效；所有授权管理命令只允许从 Tips 主窗口调用。

## 可用工具

| 工具 | 用途 |
| --- | --- |
| `tips_groups_list` | 列出当前客户端获准访问的分组 |
| `tips_group_create` | 新建持久化空分组；调用者必须由用户显式开启“允许管理分组”，成功后自动获得新组的协调权限 |
| `tips_group_rename` | 原子重命名调用者负责的分组，同时迁移便签、TODO 和全部 MCP 授权；要求“允许管理分组”及源组 `coordinator`，且 `inbox` 不可重命名 |
| `tips_items_list` | 按分组、类型、状态、更新时间和数量上限列出条目 |
| `tips_item_get` | 读取一个获准访问的便签或 TODO |
| `tips_item_create` | 在有写权限的分组中创建便签或 TODO |
| `tips_item_update` | 使用 `expectedRevision` 局部更新正文、标题、标签、截止时间或完整 TODO 清单 |
| `tips_item_move` | 使用 `expectedRevision` 把条目移动到已有分组；源组和目标组都必须有写权限 |
| `tips_item_set_status` | 将条目设为 `active`、`completed` 或 `archived` |
| `tips_todo_entry_set_completed` | 使用条目和清单项修订号勾选或恢复一个 TODO 清单项 |

`tips_item_update` 是补丁操作：未传入的标题、正文、标签和截止时间保持不变；`clearDueAt = true` 才会清除截止时间。传入 `replaceTodoEntries` 表示完整替换 TODO 清单，省略它则保留现有清单。移动分组使用独立的 `tips_item_move`，不能通过普通更新绕过目标组授权。

所有修改都需要当前修订号。若桌面端或其他 Agent 已经修改同一条目，旧修订号会得到冲突错误；客户端应重新读取条目，再基于最新数据重试。

## 数据和安全边界

- MCP 只返回普通便签和 TODO 的任务数据，不返回窗口坐标、尺寸、置顶、透明度、颜色或主题。
- 临时秘密、敏感条目和 `mcp_access = deny` 条目会在数据库选行阶段被排除，不会先解密再过滤。
- 原始 Bearer token 只显示一次；SQLite 只保存 SHA-256 哈希。
- 每次 MCP 修改和对应的 `task_events` 审计记录在同一个 SQLite 事务中提交。
- 请求体上限为 1 MiB；Host 和浏览器 Origin 只接受当前回环端点；服务还限制同时处理的请求数量。

## 常见问题

### `localhost` 或 `127.0.0.1` 拒绝连接

确认 Tips 正在运行，并在 MCP 管理面板中看到“服务运行中”。如果面板显示启动异常，通常是端口 `4784` 已被另一个进程或另一个 Tips 实例占用。客户端可以使用 `localhost`，但建议直接使用面板展示的 `127.0.0.1` 端点。

### 返回 `401 Unauthorized`

确认请求使用 `Authorization: Bearer <token>`，token 没有多余空格，并且客户端尚未被撤销。原始 token 无法从数据库恢复；不确定时撤销旧客户端并重新创建。

### 能连接但看不到条目

先调用 `tips_groups_list` 检查当前授权。条目必须属于已授权分组，并且不能是秘密、敏感或显式拒绝 MCP 的条目。`viewer` 可以读取，但不能创建或修改。

### 客户端找不到工具

确认客户端支持 Streamable HTTP 和 MCP `2026-07-28`。旧客户端如果不发送当前协议要求的标准请求头，会被服务拒绝；请升级客户端或 SDK。

任务分配、租期认领、事件游标、stdio bridge 和显式 LAN 模式的后续设计见 [`../MCP_CONTRACT.md`](../MCP_CONTRACT.md)。
